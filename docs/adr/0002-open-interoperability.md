# ADR-0002: 开放网络与独立实现互操作

Status: Accepted (principle); Protocol wire details: Proposed
Date: 2026-10-27

## Context

Raminga 应允许第三方开发客户端/Agent，也应允许任何开发者不使用官方 Node 核心代码而自行实现兼容节点。只发布 Apache-2.0 源码不足以实现这个目标：许可证处理代码使用权，而加入网络依赖公开可实现的协议、可达连接方式和一致性验证。

## Decision

1. 以开放、实现中立的跨节点协议作为互通标准，官方 Node 与第三方独立节点在协议级平等。
2. 参与基础公共网络不要求官方账号、运营商批准、官方 API Key、官方客户端或唯一官方引导/中继。已知地址和可替换公共服务是必须保留的连接路径；是否可达仍取决于网络拓扑。
3. 本地 Node API/SDK 面向应用与 Agent 操作；跨节点 wire 协议独立于实现语言和官方核心包。
4. 各节点自主执行身份验证、授权、内容可见性、阻断和反滥用策略。无需官方许可不意味着无需对端同意或允许读取私人数据。
5. 对外宣布跨实现兼容前必须冻结语言无关协议及版本、提供测试向量/一致性测试，并通过至少一个不依赖官方 Node 包的独立实现与官方实现的互通验收。

## Consequences

保留现有 node/network/protocol/identity 等模块，不新建协议服务器或强制官方注册中心。更新愿景、Node、协议、测试、MVP 和安全文档。网络 PoC、第三方使用 Node SDK、独立第三方节点的互操作是三个不同的验收目标，不能互相替代。

> **2026-11-06 更新：** 当前 Go wire 已是 HTTP `/raminga/http/1.0.0` + `/chat` JSON；下文关于旧 protobuf wire 的描述仅保留为决策历史。

当前 Go wire `/raminga/http/1.0.0` 已有 JSON 契约与测试向量；但尚无第三方独立实现互操作、真实公网发现/中继或安全接入验收。代码对外可获得性另行处理。
