# ADR-0004: TUI 使用非全屏输出

Status: Accepted（Windows 和真实网络验收未完成）
Date: 2026-11-06

## Context

`raminga tui` 主要用于调试，经常要复制地址和 Peer ID。它原来运行在备用屏幕，日志画在 Bubbles 视口里。实测发现几个同根问题：

- 超过窗口宽度的行只能切开，切开后复制会带上真实换行，粘贴到 `/connect` 报 `invalid cid`。
- 视口把每行补空格到窗口宽度，复制时会带上行尾空格。
- 不开鼠标模式时滚轮不可用，开启后又影响选中复制。
- 备用屏幕下 Bubble Tea 丢弃 `Printf`，`/copy` 通过它发送的 OSC52 没有发出。
- 日志跟随和翻页都要自己维护。

## Decision

TUI 不再使用备用屏幕：

- 日志通过串行队列调用 `tea.Println`，进入终端的普通回滚区。同一时间只有一个打印在进行，避免并发命令打乱顺序。退出前先把队列打印完。
- 程序只管理底部的状态行、输入行，以及补全列表或提示行。
- 长行不由程序折行，由终端显示折行。
- OSC52 由一次 `Write` 直接写到输出。
- 不更换 Bubble Tea，不升级 v2，不开启鼠标模式，补全列表保留现有滚动窗口。

`bubbles/list` 没有采用：它按页切换，不是逐行滚动，还会增加 `sahilm/fuzzy` 依赖，只能替代约 77 行逻辑。

## Consequences

- `/addr`、日志视口、日志内翻页都已移除。滚动、搜索和选中复制交给终端。
- `/clear` 只清当前屏幕，终端历史不受影响。
- 退出 TUI 后日志留在终端里。
- 已打印的内容不能再被程序修改，所以报告和时间线仍保留在内存里。
