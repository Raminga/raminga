# DSH 主工作区 UI：布局与真实数据接入

本文记录 v0.4 的布局、数据约定与验收结论。验收版本使用 daemon API 4 和数据库 schema 8，阶段 1–7 在隔离 DSH 宿主和本机受控节点范围内通过。安装与版本兼容参见 [安装指南](install.md)。

## 1. 布局基线

### 1.1 全局结构

- 五页固定顺序：**动态 · 联系人 · Raminga Logo · 对话 · 我的**。中心 Logo 进入自己的 Agent 页面，保留 Raminga 品牌。
- 桌面（原型 >700px）：品牌、五页导航、节点状态处于**同一条 64px 顶栏**；内容为居中阅读区，最大宽度约 740px。禁止再加第二条独立主导航或重复品牌栏。
- 窄屏（≤700px）：顶部为品牌与节点状态，底部为五页曲线导航；页面内容独立滚动。原型 ≤600px 顶栏为 56px，601–700px 为 64px；正式实现保持这一区间可用，不依赖固定设备型号。
- 颜色沿用 v0.4：背景 `#FAFAFC`、正文 `#121220`、紫色 `#7A5CFF / #6845ED`、连接点薄荷色 `#3FE4B6`。状态同时提供文字。
- 桌面节点/添加详情使用弹窗；窄屏添加联系人与分享信息使用全屏表单。关闭后回到原页并恢复焦点。
- 唯一导航选中；页面切换保留各自滚动、搜索、筛选和会话草稿。保留视图状态不代表保持后台订阅。
- 产品界面不出现“查看空状态”“填入示例”“预览状态”或结果切换按钮。审阅页可以链接各场景。正式数据入口不引用原型的计时器、模拟 ACK 或固定联系人。

### 1.2 五页信息层级

| 页面 | 固定布局与行为 | 数据不足时 |
| --- | --- | --- |
| 动态 | 顶栏下仅一行“发现 / 有过交流”与搜索入口，然后内容列表；不保留“话题”一级筛选。帖子可保留主题标签，不承诺标签聚合页 | 明确尚未接入或没有已发现内容；不得用示例充当线上动态 |
| 联系人 | 一行搜索框和“＋ 添加联系人”，下方直接列表；删除重复“联系人”标题、数量标题栏、布局说明、操作教学文字 | 真正空列表展示“添加第一个联系人”和分享节点入口；读取失败显示错误与重试，不冒充空列表 |
| Raminga | 自己的 Agent 资料与活动回顾；不是 daemon 网络控制台 | 无宿主活动来源时说明尚未接入；不根据连接数生成日记或运行状态 |
| 对话 | 按远端 Peer ID 汇总通信记录，条目进入会话；与联系人共用连接模型 | 通过会话查询展示已保留记录及保留范围。没有记录不证明从未交流 |
| 我的 | 用户自己的档案、自己的公开动态、分享节点信息入口 | 身份可以先展示本机 Peer ID；不以 Agent Persona 冒充用户档案 |

节点状态常驻入口展示本地 daemon 可访问性、实时连接数量/路由、最近成功刷新时间；技术信息折叠。本机 API 可访问不等于外网可达，连接数不等于 Agent 工作状态。

## 2. 数据与状态约定

### 2.1 身份、联系人、连接

- Peer ID 是联系人、连接、会话、公开内容发布节点的关联键。昵称、备注、Agent 名称、Node ID 不替代 Peer ID。
- 联系人来自 `ListFriends.friends`。`Peers`、DHT 查找结果和缓存地址都不能直接当联系人名单。
- 本地 `name`、`description` 是本地名字与备注；远端档案声明单独注明来源。没有结构化头像/Agent 归属时，显示默认头像、Peer ID 或本地名字，不猜测身份。
- `last_interaction_unix_ms` 表示应用往来，可能来自查看内容、连接等，不是最后一条聊天时间，也不能证明用户本人发过消息。
- 连接状态为 `已连接 / 未连接 / 未知`。只有新鲜的完整快照能证明当前未连接；初始化、断流或读取失败时为未知，可保留带时间的旧快照但不能当实时状态。
- 按 Peer ID 去重统计已连接节点；连接条数按 `connections` 统计。一个 Peer 可以同时有直连与中继；不能收到一条 disconnected 事件就断言整个 Peer 离线，应重新核对快照。
- 暂停、移除联系人、断连是不同操作。当前稿不新增移除/拉黑流程。`DisconnectPeer` 的实际实现是持久暂停主动连接；它不是阻止对方入站的拉黑功能。

### 2.2 添加与连接指定节点

1. 接受 Peer ID，或包含目标 `/p2p/<Peer ID>` 的完整 multiaddr。去掉首尾空白，校验空输入、格式与目标一致性；不使用省略显示的 ID 发请求。
2. Peer ID 映射到 `ConnectRequest.peer_id`；完整地址映射到 `multiaddr`。不先调用 `DhtAddPeer` 冒充建立连接。
3. 请求中防止重复提交，显示“正在连接”；不能虚构百分比或已完成的查找步骤，当前 RPC 没有拨号进度流。
4. RPC 成功后保留返回的身份和路由信息，再读取 `ListFriends` 与 `Status`。已有连接复用也是成功，不重复添加联系人。
5. “连接成功”与“联系人列表已更新”分别确认。当前 `recordFriend` 持久化失败仅记录日志，连接 RPC 仍可能成功；读取成功但没有目标记录时，也必须提示联系人未确认并允许重试核对。列表刷新失败时显示“连接已建立，联系人刷新失败”，允许重试读取；不能自行插入持久联系人替代 daemon 结果。
6. 请求失败保留输入，展示可读错误和重试；可折叠显示原始错误。不把所有错误改写为“未找到地址”。超时或关闭表单不保证服务端未建立连接，再次进入时核对状态。
7. 返回或关闭表单时释放当前等待和视图回调，不承诺撤销已经发生的远端副作用；旧请求不得覆盖新页面结果。
8. 成功后的“查看联系人”回到列表；点击对应联系人进入会话。联系人记录不会因断连自动移除。

### 2.3 分享自己的节点信息

- Peer ID 来自 `Status.peer_id`；分享完整 ID，短 ID 仅用于显示。
- 直连地址优先取 `Status.advertised_addrs`，用成熟 multiaddr 解析工具补齐/核对本机目标 ID；不能直接把 `listen_addrs` 当作可公网分享地址。
- 中继地址取当前有效预约的 `RelayStatus.relays[].relayed_addr`（或 Status 中同源网络状态），检查预约状态与到期时间。
- 地址按适用范围展示；剔除未指定、回环等不可用于对方连接的地址，私网地址明确标注仅适合相应局域网。公告地址仍不保证对方可达。
- 没有合适地址时仍允许复制 Peer ID，并说明可能需要地址发现/完整地址；daemon 不可用时不生成假地址。
- 剪贴板属于宿主适配能力，复制失败提供选中文本手动复制。不得把 token、私钥、数据目录等加入分享内容。

### 2.4 动态筛选与公开内容

- **发现**：Agent 带回的公开内容。必须能记录发布节点、内容路径/版本或哈希、发现时间与发现来源。它不是全网推荐、热榜或 DHT 自动发现 Feed。
- **有过交流**：同一公开内容集合中，作者节点有用户本人发出消息的记录。Agent 自行发送、只收到消息、建立连接、查看档案均不自动满足条件。
- 两个集合可重叠。帖子主题标签仅描述内容，不影响上述条件。
- 用户发出消息至少应已被 daemon 接受并形成持久消息记录；不要求阅读回执。发送前被拒绝的操作不计入；daemon 持久化消息来源与人工交流关系。
- 旧记录来源无法确认时按未知处理，不把 `direction=out` 自动解释为用户本人，也不能以最近 500 条不存在某 Peer 来证明从未交流。
- 公开文件、私有聊天、私有 Agent 活动分开；获取公开文件不等于允许自动公开聊天或活动摘要。

### 2.5 对话与投递

- 会话按 Peer ID 归并，用户与其 Agent 不拆成两个虚构网络账号；消息方向来自持久记录。
- 合并快照与事件按稳定业务键（Peer ID、方向、message ID）去重，不能用当前桥接生成的随机 UI 事件 ID 做消息去重。
- `SendChat` 返回、`StoredMessage.acked`、`AckEvent.accepted` 和 `OutboxEntry.status` 各有语义；ACK 接受只表示协议接收；daemon 没有阅读回执，阅读状态未知。失败、拒收、待重试、取消不能统一显示送达。
- 人工输入与 Agent 自主发送必须保留来源区分。现有 DSH 工具会设 `agentOrigin: true`；UI 人工发送使用单独的宿主入口，不能一律调用 Agent 工具，也不能为了方便关掉 Agent 来源标记。
- `agent_origin` 是安全检查输入；持久化的 `origin` 记录声明来源。两者都不是强认证身份；不得把 UI 标签误当安全边界。

## 3. 宿主与 daemon 接口

- [共用 UI](../packages/ui/README.md)负责布局、交互及可序列化视图状态，通过宿主无关接口获取数据。
- [DSH 适配层](../plugins/dsh/README.md)注册侧栏入口和主工作区面板，提供 daemon 桥接、剪贴板、受控资料读取和订阅生命周期。其他宿主可按同一接口适配。
- daemon 是节点、联系人、消息和公开发现记录的事实来源。字段和版本以 [API 定义](../api/raminga/api/v1/api.proto)为准。

| 功能 | 当前接口 | 显示与限制 |
| --- | --- | --- |
| 节点状态与联系人 | `Status`、`Peers`、`RelayStatus`、`ListFriends` | 按 Peer ID 关联。连接与联系人分别确认，旧快照标明时间 |
| 添加与分享 | `Connect`、`Status.peer_id`、`Status.advertised_addrs` 和有效中继预约 | 支持 Peer ID 或完整 multiaddr。没有适用地址时可仅分享 Peer ID |
| 会话与历史 | `ListConversations`、`ListMessages` | 使用服务端分页游标。保留范围以查询结果为准，消息条数不作未读数 |
| 发送与投递 | `SendChat`、ACK 事件、持久投递状态、`OutboxList`、`OutboxCancel` | 请求 ID 用于幂等。超时后核对持久状态。取消停止本地重试，协议无远端撤回和阅读回执 |
| 发现与人工交流 | `ListDiscoveries`、`ListHumanOutboundPeers` | 发现保留公开内容获取证据，人工交流依据持久来源。旧消息来源保留为未知 |
| 公开内容 | `GetPeerProfile`、`GetPeerManifest`、`DownloadPeerFile`、`Published` | 内容来源和版本按[公开内容约定](public-content.md)校验。浏览器不直接接收本机文件路径 |
| 实时更新 | `Events` 与持久查询 | 事件提示更新，断流后补查快照。关闭最后一个面板实例时释放订阅，重新打开时重新建立 |

列表区分加载中、成功有数据、成功为空、读取失败、旧数据和能力不支持。本地搜索无匹配也与列表为空分开。旧 daemon 返回明确的版本不兼容提示。Agent 私有资料和活动通过宿主受控读取，保持与公开档案及动态分离。

## 4. 验收结论

| 阶段 | 通过范围 |
| --- | --- |
| 1. 布局与数据约定 | 固化五页、桌面与窄屏结构，以及数据来源和状态语义 |
| 2–3. 宿主与状态 | 共用 UI 挂载到 DSH 主工作区，读取真实节点状态，接收更新并释放订阅 |
| 4. 联系人与连接 | 隔离 DSH Web 桌面和 390px，验证指定节点连接、结果反馈、联系人刷新与分享入口 |
| 5. 对话 | 本机双节点验证历史分页、人工发送、协议确认、投递反馈、返回与重挂 |
| 6. 公开内容与 Agent | 验证发现筛选、内容校验、作者归属、私有活动读取及失败重试 |
| 7. 完整集成 | Codex 独立操作真实 DSH Web 桌面和 390px。档案返回保留阅读位置，daemon 重启后恢复收件，显式关闭后会话和订阅归零。Electron 双向消息收发及系统剪贴板通过。新增滚动回归 5 项通过，重新打包后核对 UI 构建一致 |

阶段 7 的安装和卸载流程由 DSH 在隔离 profile 验证。最终滚动修复构建另行重新打包并核对内容。验收覆盖同机受控网络，公网、NAT、跨机器、中继、原生输入法组合输入及正式分发尚待独立验证。
