# DSH 主工作区 UI：布局与真实数据接入

本文记录三主页布局、数据约定与验收结论。P1 已由 Codex 实际复验主要流程通过，使用 daemon API 4 和数据库 schema 9；P2 使用 API 5 与 schema 10，新增公开资料/头像/图文动态、私有草稿、版本冲突、原子发布、清单摘要与双节点读取；P3 使用 API 6 与 schema 11，新增人类持久已读、联系人未读/最近消息、仅公开动态收藏、按 Peer 发现过滤、联系人主页真实交互时间线与受控私有印象编辑，并已由 Codex 复验通过。P4 按真实 `raminga_*` 工具执行记录私有活动，已由 Codex 复验通过；P5 在独立 4344/4346 真实 DSH 上完成双节点、1440×900/390×844、真实插件禁用/卸载/重装、schema 9→11 升级与旧文件兼容自测，**待 Codex 最终验收**，不宣称 P5 已通过。完整证据见 [`reports/p5-acceptance-2026-11-18.md`](../reports/p5-acceptance-2026-11-18.md)。安装与版本兼容参见 [安装指南](install.md)。

## 1. 布局基线

### 1.1 全局结构

- 三个主页固定顺序：**动态 · 主页 · 联系人**；默认进入 **主页**。`对话`、`设置`、联系人主页、动态/Journey 详情都是子页，不进入一级导航。
- 桌面（>700px）：品牌、三项主导航、设置齿轮、节点状态处于**同一条约 76px 顶栏**；内容为居中阅读区，主页最大宽度约 1056px。禁止再加第二条独立主导航或重复品牌栏。
- 宿主原生侧栏与 leading control（窗口控件/Logo）保持可见可操作。插件根节点建立独立 stacking context，顶栏层级不得越过宿主侧栏；顶栏左侧使用宿主继承的 `--dsh-frame-leading-clearance`（缺省保持现有 32px 间距），不新建第二侧栏。
- 窄屏（≤700px）：顶部为品牌、设置与节点状态，底部为三项固定导航；页面内容独立滚动。≤700px 顶栏/底栏约 65px，Agent 形象约 182px，人类条压缩为次要信息。
- 颜色采用最新三页原型：背景 `#FAF9FE`、正文 `#171426`、次级正文 `#4B445E`、弱化 `#827990`、品牌紫 `#7A5CFF`、交互紫 `#6845ED`、薄荷 `#3FE4B6`、珊瑚 `#FF7F6E`。状态同时提供文字。
- 桌面节点/添加详情使用弹窗；窄屏添加联系人与分享信息使用全屏表单。关闭后回到原页并恢复焦点。
- 唯一一级导航选中；子页打开时仍选中其最近的一级页。页面切换保留各自滚动、搜索、筛选和会话草稿。保留视图状态不代表保持后台订阅。
- 产品界面不出现“查看空状态”“填入示例”“预览状态”或结果切换按钮。正式数据入口不引用原型的计时器、模拟 ACK、暂停开关或固定联系人。

### 1.2 三主页信息层级

| 页面 | 固定布局与行为 | 数据不足时 |
| --- | --- | --- |
| 动态 | “发现 / 有过交流 / 我的动态”三项筛选与搜索；只列可识别的版本化公开帖子（v1 旧帖与 v2 图文帖）。标题/摘要进入独立帖子详情，详情返回恢复筛选、搜索、滚动与焦点；配图可独立预览，来源详情、受控定位、收藏与本人/Agent 编辑入口保留。普通文件、通讯录、资料和帖子配图资产不进入动态。列表与详情的发布者头像跟随页头身份：人类公开名用人类头像，Agent 公开名用 Agent 头像，未知/缺失/损坏/版本不符回退首字；我的动态复用本机公开资料头像，且列表不为每张卡发起远端头像读取。明确点击刷新才启动有界远端检查，其他进页/TTL/搜索/被动重读只读本地索引 | 明确尚未接入或没有公开帖子；不得用示例充当线上动态。我的动态只列本机 `public/posts/`，按真实作者声明标“本人/Agent/来源未注明” |

## 2. 数据与状态约定

### 2.1 身份、联系人、连接

- Peer ID 是联系人、连接、会话、公开内容发布节点的关联键。昵称、备注、Agent 名称、Node ID 不替代 Peer ID。
- 联系人来自 `ListFriends.friends`。`Peers`、DHT 查找结果和缓存地址都不能直接当联系人名单。
- 本地 `name`、`description` 是本地名字与备注；远端档案声明单独注明来源。没有结构化头像/Agent 归属时，显示默认头像、Peer ID 或本地名字，不猜测身份。联系人头像、姓名和主体入口都打开对方个人首页；会话入口在个人首页的“发消息”中，失败时仍可进入原会话。
- 本地名字/备注通过同一个编辑表单修改，入口是联系人档案主视图、联系人列表快速菜单和会话头部快速菜单。两者可独立留空清除；空名字显示短 Peer ID，空备注不占位。非空名字仍校验格式并保持唯一；留空字段不会误清另一个字段。保存只会更新本机联系人记录与公开的 `friends.json`，**不会**修改远端档案。
- `last_interaction_unix_ms` 表示应用往来，可能来自查看内容、连接等，不是最后一条聊天时间，也不能证明用户本人发过消息。
- 连接状态为 `已连接 / 未连接 / 未知`。只有新鲜的完整快照能证明当前未连接；初始化、断流或读取失败时为未知，可保留带时间的旧快照但不能当实时状态。
- 按 Peer ID 去重统计已连接节点；连接条数按 `connections` 统计。一个 Peer 可以同时有直连与中继；不能收到一条 disconnected 事件就断言整个 Peer 离线，应重新核对快照。
- 暂停、移除联系人、断连是不同操作。当前稿不新增移除/拉黑流程。`DisconnectPeer` 的实际实现是持久暂停主动连接；它不是阻止对方入站的拉黑功能。

### 2.2 添加与连接指定节点

1. 接受 Peer ID，或包含目标 `/p2p/<Peer ID>` 的完整 multiaddr。去掉首尾空白，校验空输入、格式与目标一致性；不使用省略显示的 ID 发请求。
2. Peer ID 映射到 `ConnectRequest.peer_id`；完整地址映射到 `multiaddr`。不先调用 `DhtAddPeer` 冒充建立连接。
3. 请求中防止重复提交，显示“正在连接”；不能虚构百分比或已完成的查找步骤，当前 RPC 没有拨号进度流。
4. RPC 成功后保留返回的身份和路由信息，再读取 `ListFriends` 与 `Status`。已有连接复用也是成功，不重复添加联系人。
5. “连接成功”与“联系人列表已更新”分别确认。当前 `recordFriend` 持久化失败仅记录日志，连接 RPC 仍可能成功；读取成功但没有目标记录时，也必须提示联系人未确认并允许重试核对。列表刷新失败时显示“连接已建立，联系人刷新失败”，允许重试读取；不能自行插入持久联系人替代 daemon 结果。
6. 请求失败保留输入，展示可读错误和重试；可折叠显示原始错误。不把所有错误改写为“未找到地址”。超时或关闭表单不保证服务端未建立连接，再次进入时核对状态。
7. 返回或关闭表单时释放当前等待和视图回调，不承诺撤销已经发生的远端副作用；旧请求不得覆盖新页面结果。
8. 成功后的“查看联系人”回到列表；点击对应联系人进入会话。联系人记录不会因断连自动移除。

### 2.3 分享自己的节点信息

- Peer ID 来自 `Status.peer_id`；分享完整 ID，短 ID 仅用于显示。
- 直连地址优先取 `Status.advertised_addrs`，用成熟 multiaddr 解析工具补齐/核对本机目标 ID；不能直接把 `listen_addrs` 当作可公网分享地址。
- 中继地址取当前有效预约的 `RelayStatus.relays[].relayed_addr`（或 Status 中同源网络状态），检查预约状态与到期时间。
- 地址按适用范围展示；剔除未指定、回环等不可用于对方连接的地址，私网地址明确标注仅适合相应局域网。公告地址仍不保证对方可达。
- 没有合适地址时仍允许复制 Peer ID，并说明可能需要地址发现/完整地址；daemon 不可用时不生成假地址。
- 剪贴板属于宿主适配能力，复制失败提供选中文本手动复制。不得把 token、私钥、数据目录等加入分享内容。

### 2.4 动态筛选、公开文件预览与来源标签

- **发现**：本机记录的手动获取或 Agent 获取公开内容。必须能记录发布节点、内容路径/版本或哈希、发现时间与获取来源；同一版本同时有手动和 Agent 获取时都保留。它不是全网推荐、热榜或 DHT 自动发现 Feed。动态的三项筛选只展示已识别的版本化公开帖子；非帖子获取记录在宿主桥接层即被排除并计数，搜索、计数与分页使用同一帖子口径。普通文件、通讯录、公开资料和历史下载副本保留在独立的“公开文件”入口，不从动态卡片伪装成帖子。
- **有过交流**：同一公开内容集合中，作者节点有用户本人或真实 Agent 实际发出消息的记录。只收到消息、建立连接、查看档案、仅联系人记录或 `last_interaction` 均不自动满足条件。显式刷新读取的候选集与后端口径一致：发现范围是本机已有版本化帖子收录记录的发布节点 ∪ 实际发出过消息的节点，有过交流只取后者。检查预算、跳过同版本、同路径新 SHA、失败保留旧卡片和“不轮询/不自动下载”的语义见 [公开内容约定](public-content.md#4-私有发现索引)。
- 两个集合可重叠。帖子主题标签仅描述内容，不影响上述条件。
- 用户发出消息至少应已被 daemon 接受并形成持久消息记录；不要求阅读回执。发送前被拒绝的操作不计入；daemon 持久化消息来源与人工交流关系。
- 旧记录来源无法确认时按未知处理，不把 `direction=out` 自动解释为用户本人，也不能以最近 500 条不存在某 Peer 来证明从未交流。
- 卡片标题使用发布节点公开名，fallback 短 Peer ID；原 JSON 帖子的作者声明只在来源详情中显示。普通 Markdown 使用第一个 h1（无 h1 时用文件名）；文本/代码/普通 JSON 为安全文本；图片、音频、视频用原生元素并按需加载；单 HTML 只内联文档自身的 data URI，相对/外部资源报告缺失；带唯一 `index.html` 的 ZIP 在 sandbox + CSP 中预览，包内资源随 ZIP 整体校验。
- 预览状态区分不支持预览、尚未下载、本地副本缺失、大小/哈希不符、ZIP 错误和关联资源不完整。旧发现绑定原 SHA-256；本地副本被覆盖后不展示新版。
- “在文件夹中显示”只定位本地已下载或本人已发布原件，浏览器不获得任意路径；发现提交记录 ID，对方首页和设置中的公开文件提交 Peer ID/路径/哈希，宿主对照当前清单或 `Published` 清单并在 `downloads/<peer>/` 或 `public/` 内校验后调用 DSH Host 的 reveal-only 能力。未下载或版本不符不会定位成功。
- 对方首页优先读取本机已核对副本，只有当前远端清单可用且确需获取时才下载；对方离线时可用持久 `ListDiscoveries` 和受控副本证据恢复**本地历史副本**列表，并明确标注它不是当前远端完整清单。
- 公开文件、私有聊天、私有 Agent 活动分开；获取公开文件不等于允许自动公开聊天或活动摘要。

### 2.5 对话与投递

- 会话按 Peer ID 归并，用户与其 Agent 不拆成两个虚构网络账号；消息方向来自持久记录。
- 合并快照与事件按稳定业务键（Peer ID、方向、message ID）去重，不能用当前桥接生成的随机 UI 事件 ID 做消息去重。
- `SendChat` 返回、`StoredMessage.acked`、`AckEvent.accepted` 和 `OutboxEntry.status` 各有语义；ACK 接受只表示协议接收；daemon 没有阅读回执，阅读状态未知。失败、拒收、待重试、取消不能统一显示送达。
- 人工输入与 Agent 自主发送必须保留来源区分。现有 DSH 工具会设 `agentOrigin: true`；UI 人工发送使用单独的宿主入口，固定 `origin=human`，不提供手动冒充 Agent 的来源选择。P2 发布默认署名为本人，工具发布署名为 Agent；P1 不新增手动切换来源能力。
- 出站消息按已知 `human`/`agent` 来源使用各自公开头像或稳定默认形象；入站只证明认证 Peer，无法可靠区分该 Peer 下具体作者时保持中性，不借对端档案头像冒充当前作者。发送状态、技术详情和重试是输入框上方的独立浮层，不属于输入表单的滚动区域；空状态不保留空白高度。失败任务的草稿保留在输入框；失败或结果未知时重试复用原 `request_id`，未知超时只读持久记录核对，不把“重试”伪装成新消息或已送达。
- `agent_origin` 是安全检查输入；持久化的 `origin` 记录声明来源。两者都不是强认证身份；不得把 UI 标签误当安全边界。

### 2.6 Agent 工具活动（P4）

- 唯一写入者是 DSH 插件的 `defineRamingaTools` execute 包装层。手动连接、打开档案、下载/预览、发消息、标记已读、收藏、刷新和 UI 轮询都不写活动日志。
- 日志固定为 `<data-dir>/agent/activity.jsonl`：`0700` 目录、`0600` 文件、append-only、每行一个 JSON、单行 ≤ 8 KiB，超过 4 MiB 轮转为 `activity.1.jsonl`（保留一份）。只写入 ID/相对公开路径/哈希/消息 ID/发现 ID，不写入聊天正文、资料正文、草稿正文、token、绝对路径或本机下载路径。
- 每次真实调用独立 `operation_id`；并发不合并，重试是新操作。`plugin_instance_id` 每次 `apply` 更换；面板关闭只解绑 `panel_session_id`，不写终态。插件 `dispose()` 对仍无终态的操作写 `interrupted`，晚到的真实 `finished(ok)` 作为最后终态覆盖；下次启动把旧实例孤儿 `started` 标为 `unknown`（`host_restart`），不重试。
- 包装层 120 秒超时写 `timeout` 并向 Agent 返回“结果可能仍未知”，不声称底层未执行。`timeout`/`interrupted`/`unknown` 都不是 `failed`。
- Journey 关联只用于解释上下文：扫描 `status=running` 的 session；恰好一个时按目标 Peer 标 `current_peer`/`visited_peer`，未访问候选仍标 `active_journey`；无 running 为 `none`，多个 running 不猜测为 `ambiguous`。`journey_id` 是本地引用，不是远端证明；UI 跳转优先 Journey，其次联系人/会话，最后明确“本机没有可跳转证据”。
- 主页活动卡与“正在访问”合并为一张卡，保留原型 orb、状态徽标和 chevron；无目标也不隐藏。详情分开显示“本机工具调用记录”（事实）与“Agent 生成的 Journey 摘要”（叙事），包含路由/证据摘要、来源、消息 ID 和历史；旧实例记录只在显式历史里标“上次实例”。
- 读取失败/权限错误/坏行超限显示错误态，不冒充空列表；`activity.jsonl` 不存在才显示无记录。`panel-runtime` 在 `dispose()` 递增 generation，丢弃晚到的 `activity` 结果；bridge 调用失败会清空“运行中/正在访问”实时态。

## 3. 宿主与 daemon 接口

- [共用 UI](../packages/ui/README.md)负责布局、交互及可序列化视图状态，通过宿主无关接口获取数据。
- [DSH 适配层](../plugins/dsh/README.md)注册侧栏入口和主工作区面板，提供 daemon 桥接、剪贴板、受控资料读取和订阅生命周期。其他宿主可按同一接口适配。
- daemon 是节点、联系人、消息和公开发现记录的事实来源。字段和版本以 [API 定义](../api/raminga/api/v1/api.proto)为准。

| 功能 | 当前接口 | 显示与限制 |
| --- | --- | --- |
| 节点状态与联系人 | `Status`、`Peers`、`RelayStatus`、`ListFriends`、`ListBootstrapPeers`/`AddBootstrapPeer`/`RemoveBootstrapPeer` | 按 Peer ID 关联。连接与联系人分别确认，旧快照标明时间。右上角只负责本机：刷新本机、分享本机信息、查看/添加/移除/刷新引导节点（节点设置，不是联系人；在线状态单独显示） |
| 添加与分享 | `Connect`、`Status.peer_id`、`Status.advertised_addrs` 和有效中继预约 | 支持 Peer ID 或完整 multiaddr。没有适用地址时可仅分享 Peer ID |
| 会话与历史 | `ListConversations`、`ListMessages` | 使用服务端分页游标。保留范围以查询结果为准，消息条数不作未读数 |
| 发送与投递 | `SendChat`、ACK 事件、持久投递状态、`OutboxList`、`OutboxCancel` | 请求 ID 用于幂等。超时后核对持久状态。取消停止本地重试，协议无远端撤回和阅读回执 |
| 发现与人工交流 | `ListDiscoveries`、`ListDiscoveryRefreshPeers`、`ListHumanOutboundPeers` | 发现保留公开内容获取证据，人工交流依据持久来源。旧消息来源保留为未知；刷新候选只读本地关系与索引事实，不拨号 |
| 公开内容与发布 | `GetPeerProfile`、`GetPeerManifest`、`GetPeerFriends`、`DownloadPeerFile`、`ListDiscoveries`、`ListDiscoveryRefreshPeers`、`Published`；`GetPublicDraft`、`ListPublicDrafts`、`SavePublicDraft`、`PutPublicDraftImage`、`GetPublicDraftAsset`、`ImportPublicPost`、`DeletePublicDraft`、`PublishPublicDraft` | 对方主页优先读取已核对本地副本，缺失时才按当前清单手动下载并记录 `raminga_ui_manual`；离线时用持久发现记录恢复本地历史副本。通讯录只读 `GetPeerFriends` 的公开声明，不与本机联系人混同；非帖子公开文件独立展示。Mine 只列 `Published` 清单。内容来源和版本按[公开内容约定](public-content.md)校验。浏览器不直接接收本机文件路径。草稿只在 SQLite；草稿缩略图按 draftId+assetId 受控读取并释放 object URL；我的动态可直接导入旧 v1/v2 帖子编辑，发布更新原路径；发布锁内两次重验版本与公开哈希，发布回执来自同一清单快照 |
| Agent 工具活动 | 宿主 `ramingaUi.activity(sessionId, limit)`、`ramingaUi.activityDetail(operationId)`；私有 `agent/activity.jsonl` | 只读已脱敏操作，不返回工具参数正文。`activity` 返回 `{operations, instanceId, readAt, truncated, badLines, error}`；`activityDetail` 只附加 Journey state 摘要/存在性，不返回 report/events/persona。面板关闭不写终态 |
| 实时更新 | `Events` 与持久查询 | 事件提示更新，断流后补查快照。关闭最后一个面板实例时释放订阅，重新打开时重新建立 |

列表区分加载中、成功有数据、成功为空、读取失败、旧数据和能力不支持。本地搜索无匹配也与列表为空分开。旧 daemon 返回明确的版本不兼容提示。Agent 私有资料和活动通过宿主受控读取，保持与公开档案及动态分离。
