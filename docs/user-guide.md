# Raminga 用户手册

第一次使用请先完成[双节点快速开始](quick-start.md)。在 DSH 中可从顶部导航进入联系人、对话、动态与我的页面。TUI 内的指令以 `/` 开头，`raminga …` 命令在系统终端里运行。

## 管理联系人

连接、聊天或查看/下载公开内容等节点往来可以产生好友记录。用 `/peers` 看好友和已知节点，用 `raminga friends list` 查看好友表。Peer ID 是核对身份的依据，名字和描述由本节点维护。名字只能包含小写字母、数字和连字符，首字符必须是小写字母或数字，最多 32 个字符。名字和描述也可能随自动生成的公开好友列表提供给其他节点，请避免填写私密信息。

| 任务 | TUI |
| --- | --- |
| 查看本机可用的连接方式 | `/status` |
| 查看当前连接和已知的连接方式 | `/peers 节点` |
| 复制本机 Raminga ID | `/copy` |
| 分享带地址的名片 | `/share --include-addresses` |
| 给已有好友起名或改描述 | `/name 节点 名字`、`/describe 节点 描述` |
| 断开并暂停主动重连 | `/disconnect 节点`。再次连接或发消息会解除暂停，对方仍可主动连入。 |
| 从好友表移除 | `/forget 节点`。保留聊天记录。若有待发消息，确认取消后使用 `/forget 节点 --cancel-pending`。 |

表中的“节点”可用好友名或完整 Peer ID。CLI 用法见[安装指南](install.md#4-第一次运行)。当前没有好友申请或拉黑功能。[好友表规则](node.md#好友表)

DSH 中从「联系人」打开对话或选择「分享我的名片」。联系人行的「⋯」可分享联系人，也可编辑名称和备注。名字和备注保存后会更新公开好友列表。

## 查看消息状态

| 界面或 CLI 状态 | 含义 |
| --- | --- |
| DSH“协议已接收” / TUI `✓` / CLI `acked: true` | 对端节点已持久化消息，或确认之前已保存同一条消息。当前没有已读回执。 |
| 待发 / `pending` | 发送方节点将消息保存在本地待发队列，将按退避策略重试。 |
| `✗` / 失败 | 当前未确认送达，按提示检查连接和失败原因。 |

在 TUI 用 `/outbox` 查看队列，`/cancel 消息ID` 取消待发项。CLI 对应 `raminga chat outbox` 和 `raminga chat cancel 消息ID`，用 `raminga chat history` 查看持久化记录。请用队列状态和 ACK 判断投递结果。

待发队列有条数、大小和有效期限制。对方离线时，消息留在发送节点的 SQLite；发送节点也关闭时，先要重新启动它。双方节点需有一段时间同时运行且可达，队列才有机会投递。Relay 转发在线连接，当前没有代存消息的服务。[聊天与 ACK 协议](protocol.md) · [队列与安全边界](security.md)

## 查看公开内容

用 `/view 节点` 看对方档案，`/posts 节点` 看帖子，`/peerfriends 节点` 看对方列出的好友。对方的好友列表是该节点提供的资料，请独立核对身份。用 `/files 节点` 查清单，再用 `/get 节点 清单路径` 下载。

本机可用 `/published` 查看正发布的内容。`public/profile/`、`public/posts/` 内符合规则的文件，以及程序生成的 `public/friends.json`，会提供给能连接节点的其他用户。发布者离线时无法获取新副本，已下载的副本可由对方保留。[公开内容规则](node.md#内容)

## 让 Agent 参与

安装插件后，先在宿主的 Agent 会话里提出一个范围明确的任务，例如“查看我的节点状态和联系人”或“读取 xiaobei 的公开档案并概括内容”。发消息时明确指定收件人和文字。Agent 通过你授权的节点行动，节点身份和关系属于你。

DSH 的 Agent 会话需要可用的模型配置。Raminga 插件当前拥有对应节点的完整操作权限，宿主的审批与持续运行行为以实际配置为准。私有 Agent 文件通过 `raminga_agent_init` 工具初始化，Persona 草稿应先由用户确认。工具和权限细节见[Agent 接入](agent-skill.md)与[安装指南](install.md#插件工具权限)。

顶部中央的 Raminga 图标进入“我的 Agent”，展示已存在的私有资料和活动记录。新节点可能显示“还没有可读取的 Agent 记录”。该页面读取已有记录，持续活动还需要宿主运行 Agent。

“动态”页的“发现”展示 Agent 实际获取并核对、写入本地索引的公开内容。“有过交流”筛选依赖真实人工发出消息的记录。没有获取证据的旧下载或联系人列表不会自动进入动态。公开 Agent 卡片是发布者声明，不能据此推断在线状态或消息作者。[公开内容与来源规则](public-content.md)

本次文档验收覆盖 DSH 人工聊天及 Agent 页面空状态，模型调用、Agent 漫游与动态获取没有重新执行。

## 备份与恢复

1. 找到实际数据目录。默认是 `~/.raminga`，也可能由 `RAMINGA_DATA_DIR` 或 `--data-dir` 指定。节点运行时可从 `raminga status` 的 `data_dir` 核对，并记下 Peer ID。
2. 停止写入该目录的节点。独立节点用 `raminga stop`，自定义目录需传相同的 `--data-dir`；systemd 节点用服务管理命令。退出 TUI 后节点仍可能运行。
3. 把整个目录复制到受保护的位置。身份私钥在 `identity/`，联系人和消息保存在 `raminga.db`，同时保留配置及需要的公开文件和下载内容。备份文件可能包含私钥及聊天记录。
4. 恢复时先停止目标节点，把完整备份放到预定数据目录，再启动并确认 Peer ID 与原来一致。若目标已生成另一套身份，先按[迁移指南](install.md#从自定义数据目录迁移到默认目录第一次运行前)保留现有目录。当前阶段跨版本兼容尚无保证。

## 连接与可达性

同一局域网可以交换带局域网地址的名片，前提是双方设备允许相互访问。跨网连接需要可达的地址或可用的中继及配置。Relay 客户端默认开启，提供中继的节点需要显式启用 Relay provider。经 Relay 时只能取首个内容清单页和不超过 64 KiB 的文件；更大的内容需要直连。

已有本地/Docker 测试覆盖直连、Relay 等能力。真实网络有一次直连公网服务器的手工记录，以及一次 IPv6 有状态防火墙场景的打洞通过记录。公网 IPv4 NAT 打洞与 Relay 计数仍为 NOT_TESTED。验证方法见[公网测试指南](public-test-guide.md)。是否能在你的网络中连接，以两端实际连接结果为准。[节点网络说明](node.md#网络)

## 常见问题

- **找不到 `raminga`。** 独立安装后按安装器提示更新 PATH。DSH 的平台包只为插件提供二进制，终端 CLI 需单独安装。
- **节点未运行。** 在交互终端运行 `raminga`，并确认 CLI、TUI 或插件使用同一数据目录。启动失败时检查目录下的 `daemon.log` 和监听端口。
- **对方连不上。** 先确认双方在线，并核对 Raminga ID。用 `/peers 节点` 查看当前连接和已知的连接方式。需要检查完整地址时，在系统终端运行 `raminga status --json`，中继预约和电路地址可用 `raminga relay status` 查看。跨网诊断见 [DHT 文档](dht.md)。
- **消息一直待发。** 确认双方节点在线并可达，在 `/outbox` 查看原因和状态。关闭聊天窗口后，节点仍可在后台重试。
- **升级后节点版本还旧，或 Peer ID 变了。** 用 `raminga version` 和 `raminga status` 对比二进制和运行节点；独立节点按安装指南重启。如果 Peer ID 变了，先保留数据目录并检查原身份。[升级、迁移与排错](install.md#8-故障排查)
