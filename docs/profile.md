# 节点档案（Node Profile）

Status: Current（第一版公开档案已实现）· Proposed（对内视图、细粒度 Operator 授权）。2026-11-07。

档案为访问方提供节点特征，为获操作权限的主体提供节点的兴趣、上下文和可用资料。档案属于 Node，而不是某个 Agent 的模型记忆。

## 对外视图 Public Profile

**第一版已实现，且只有公开内容。** 公开档案就是数据目录 `public/profile/` 里的文件：`profile/index.md` 的第一个标题作为显示名称，正文作为介绍；没有 `index.md` 时显示文件列表或 Peer ID。`public/posts/` 里的文件同样是公开内容，`public/friends.json` 由程序生成并公开。读取方通过 `/manifest` 和 `/files/<path>` 获取，细节见 [features.md](features.md) 的第一版路线和 §5。

- 没有“白名单字段投影”：当前 Go 实现没有单独的 Profile 表或 `toPublicProfile()`，公开的就是 `public/` 下的文件；也没有隐藏的内部字段需要过滤。
- 没有按关系、按字段或按用途的可见范围；第一版不设非公开内容。“对外”不等于所有字段都面向全网——这句话描述的是未来设计，不是当前能力。
- 没有签名清单；读取方只校验文件哈希，Peer ID 由 libp2p 连接认证。发布者离线时内容不可用。

**未来（未实现，不是当前承诺）：** 公开、关系内可见、单独授权等分级；按字段导出；远端缓存/转发公开内容。这些方向见 [features.md §5](features.md)，当前代码没有实现，不能据此声称已有访问控制。

## 对内视图 Internal Context

**未来设计，当前未实现。** 目标是让获授权主体读取节点偏好、私密说明、历史摘要和关联资料；权限需要限定主体、用途与范围，未获授权者不得读取。当前数据目录里没有这样的内部档案存储，公开文件夹之外也没有由 Node 提供的“对内视图”接口。

如果以后实现，内部上下文应与 `public/` 明确分开，不能因为文件放在公开目录就被当成内部资料；社交历史仍属于 Social，由 Node 按授权组合查询结果，而不是复制一份永远更新的历史数据库。具体 schema、存储位置和授权模型尚未确定。

## Operator 授权

**当前是“全有或全无”，不是细粒度授权。**

- 本地 API 使用 UDS + token 0600；token 等于节点全部权限。能读数据目录、拿到 token 的主体就是 Operator。
- 用户主动安装的 DSH 插件（G5，未实现）在安装后拥有完整权限，不设插件内的能力边界；这是 [features.md §10](features.md) 的当前方向。插件不是第二个状态源，也不绕过本地 API。
- “对内视图只给获授权 Operator”是未来目标，不是现在的实现。按主体、用途、范围限制权限，以及撤销传播，都还没有代码。

**需要区分的两件事：**

1. **内容可见性**：第一版只有公开内容；Operator 授权不会把公开内容变成私密，也不会让未授权节点读到更多。
2. **操作权限**：当前由本地文件权限 + API token 决定，安装后的 DSH 插件继承全部权限。未来是否要在“全权限”之外增加更细的 Operator 范围，这是未决设计，不应在文档里写成已实现或已经确定。

早期“权限必须显式、可验证、默认拒绝”的表述保留为未来设计目标，不描述当前状态；当前实现没有可验证的 Operator 权限模型。

## 数据来源与一致性

当前公开档案的唯一来源是 `public/profile/` 和 `public/posts/` 里的文件；`friends.json` 的唯一准确来源是 SQLite 好友表，由程序原子重写。内容扫描、清单和哈希由 `internal/content` 负责，远端读取由 `internal/node` 负责。没有独立的 Profile 模块数据库，也没有 Profile 与 Social 两份状态互相复制的问题。

## 后续验收

- 当前：公开文件夹里的内容能被读取方按清单取到；符号链接、隐藏/临时文件和超限文件不发布；`friends.json` 只包含公开字段。
- 未来（未实现）：内部上下文不泄漏到公开区；无授权不得读取内部上下文；撤销后不能继续使用权限；动态历史由单一事实源产生。以上是设计目标，不是当前验收结果。
