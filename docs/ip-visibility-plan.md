# Raminga 隐藏 IP 与分享码实现方案

DSH 支持分享自己、分享已有联系人，以及预览分享码后连接。CLI 用 `raminga share [联系人 Peer ID]` 复制 ID，添加 `--include-addresses` 生成带地址的短码。`raminga connect <分享码>` 用于连接，TUI 对应 `/share` 和 `/connect`，其中 `/share --include-addresses` 可选入已知的局域网地址。现有网络采用直连、打洞和中继，严格依赖中继的对端 IP 隐私属于后续设计。

## 隐藏 IP 的范围

| 场景 | 用户可以看到什么 |
| --- | --- |
| 普通界面和业务接口 | Raminga ID、联系人名称、在线状态、连接方式和简明错误。 |
| 高级网络与诊断 | 本机授权后查看或复制原始 Multiaddr、拨号尝试和 DHT 状态，也可手动输入地址。 |
| 仅身份的分享码 | 持有者可读取 Raminga ID，并尝试通过已知地址或 DHT 找到节点。 |
| 带连接地址的分享码 | 持有者可解码地址并二次转发。生成时提示这一点。 |
| 网络和公开数据 | 直连对端能看到连接 IP。DHT 公告和现行 `public/friends.json` 也可能公开地址。中继能看到直接连接到它的节点 IP 和连接元数据。 [Circuit Relay v2 规范](https://raw.githubusercontent.com/libp2p/specs/master/relay/circuit-v2.md) |

若后续要向通信对端隐藏真实 IP，需强制应用流量走中继，同时封住直连、DCUtR 升级、Identify、DHT 和其他公开数据中的直接地址暴露路径。中继可由兼容节点运营，仍需有可达的中继及有效预约。

## 身份和分享码

- **Raminga ID** 直接使用当前 Ed25519 密钥派生的 libp2p Peer ID。换 IP、端口或中继时，保留同一把密钥即可沿用 ID。联系人以完整 Peer ID 去重。现有逻辑 `node_…` 缺少独立签名绑定，继续作为内部字段。 [身份实现](../internal/identity/identity.go) · [节点身份说明](node.md#身份)
- **分享码** 是可长期保存、转发的联系人名片。仅身份时使用裸 Raminga ID。带地址时使用无前缀的 Base64URL，版本位放在首个标记字节。客户端用码内 32 字节 Ed25519 公钥恢复 ID，并在连接握手时验证远端身份。
- **拨号线索** 使用二进制 IP 和端口。TCP、QUIC 共享同一地址字段，两个直连 IP 的端口相同时只编码一次端口。最多带 IPv4、IPv6 各一个地址和一条公网中继。单 IPv4 为 52 字符，双栈共用端口为 74 字符，双栈端口不同时为 76 字符。生成和解析共用公网地址检查，未验证的短码地址只作为本次拨号候选。 [短码实现](../internal/contactcard/compact.go)
- **旧名片** 中带前缀的 `v3` 和带签名的 `v2` 都可导入和连接。v2 保留信封签名验证和地址记录的序列比较。换网后的地址继续按同一 ID 从 DHT 查找。 [旧名片解析](../internal/contactcard/card.go)

## 分享自己与推荐好友

| 操作 | 地址来源和行为 |
| --- | --- |
| 分享自己 | 从当前公告地址和有效中继预约中筛选连接线索。 |
| 分享好友 | 按本地联系人 ID 从现有出站连接、PeerStore 和保存的好友地址中筛选连接线索。已有地址记录时，好友离线也能生成。 |
| 转发已收到的名片 | 可以原样转发。名片内地址过时时，接收方仍可解析 ID 并重新发现。导入后也可以从联系人页分享当前已知地址。 |
| 在对话里发送名片（后续设计） | 用单独一条消息承载分享码，复用现有聊天文本和离线投递。仅在接收方主动选择添加时发起连接。 |

三个分享入口共用「复制名片」按钮，并横排显示公网直连、中继连接、局域网直连三个复选项。可用的选项默认选中，全部取消时只分享 ID。对方将拿到的 ID 或短码粘贴到「添加联系人」，预览后选择连接。粘贴预发布的 `v1` 分享码或旧分享链接时，界面提示重新复制名片。

短码中的地址是分享者掌握的拨号线索。收件人可读取其中的 IP 和端口。名片预览只读取 ID 和地址存在性。用户选择连接后才开始拨号，连接成功后保存实际验证的对端地址，并继续从 Identify 或 DHT 获取候选。 [拨号路径](../internal/network/dial.go)

## 连接与换 IP 回退

1. DSH、TUI 和 CLI 共用 daemon 的名片校验。普通入口接受裸 Raminga ID、无前缀短码、带前缀的 `v3` 短码和 `v2` 签名码。显式 Multiaddr 参数供高级入口及既有调用方使用。
2. 解析分享码时限制大小并检查地址。v2 还需验证签名，按序列选择已知的新记录。有效地址给出一组临时拨号候选。格式错误或未知版本会在预览时返回输入错误。
3. 优先复用已验证的现有连接。需要新拨号时，将合规名片候选与 PeerStore 和 SQLite 中的已知候选去重，由现有拨号器调度。若名片含接收端当前网段的局域网地址，先尝试同网拨号。随后使用其余候选，已有 DHT 条件时并行查找，以免被旧地址拖住。
4. 按 Peer ID 查询 Raminga DHT 的 `/raminga-addr/<peer-id>` 签名记录。如果该记录缺少可用的新候选，或候选均拨号失败且仍有时间预算，再用 `FindPeer`。保留现有的中继候选和打洞策略。连接后校验远端 Peer ID，再执行现有联系人登记与 `/hello` 流程。 [DHT 发布与诊断](dht.md#5-地址记录发布) · [现有拨号路径](../internal/network/dial.go)
5. 找不到地址或拨号失败时，显示「暂时无法连接此节点」，让用户保留名片并重试。若目标换了密钥，原名片仍指向旧身份。DHT 恢复需要可用路由、目标重新发布地址和一条可达路径。

例如 A 换了网络，B 把旧分享码发给 C。C 仍能读出 A 的 ID。如果 A 的新地址已发布且可达，C 可以用旧码连上 A。DHT 尚未查到时，C 可以稍后用同一旧码重试。旧 IP 即使已分配给其他节点，libp2p 也会校验远端身份。

## 仓库改造与兼容

| 层 | 改造内容 |
| --- | --- |
| Go daemon | 新增名片编解码、签发、地址策略和保存逻辑。将名片的多地址候选接入按 ID 拨号，复用其 DHT 回退逻辑。显式地址由现有 `DialMultiaddr` 按单条路径处理。 [拨号实现](../internal/network/dial.go) |
| 本地 API | 给认证本地 API 添加名片生成和解析能力。为 `ConnectRequest` 添加 `share_code`，与显式 Peer ID、Multiaddr 参数互斥。普通客户端请求面向界面的响应，仅取得 ID、连接结果和可展示的错误。原始地址、尝试记录和底层错误由兼容旧客户端的原接口或高级诊断读取。 [本地 API 定义](../api/raminga/api/v1/api.proto) |
| DSH Web、TUI 和 CLI | 替换 DSH 当前从 `Status` 组装地址清单的分享逻辑。联系人页、聊天、添加联系人、常规状态及剪贴板使用新名片和业务数据。覆盖普通页面收到的字段、提示和错误，确保原始地址从业务接口到界面都不外溢。 [DSH 分享桥接](../plugins/dsh/src/ui-bridge.ts) · [共享界面](../packages/ui/src/app.js) |

名片地址策略由 daemon 执行。公网选项支持公网 TCP、QUIC 和结构有效的公网 Circuit Relay v2 地址。局域网选项支持 RFC 1918 和 IPv6 ULA 的直接地址，并使用向后区分的短码扩展。公网短码格式不变。地址使用 IP 字面量，排除回环、链路本地、特殊用途和不支持的协议。现有 DHT 发布可包含经私网中继的电路地址，名片额外验证中继入口。收到含禁用地址的有效 v2 信封时只保留 ID。收到含禁用地址的 v3 短码时返回输入错误。使用现有拨号总时限和限流，地址和尝试细节留在本机授权诊断。 [地址检查](../pkg/publicpeeraddr/publicpeeraddr.go)

## 实施顺序与验收

1. **daemon 与本地 API。** 验证无前缀短码和旧 v3 的长度、地址及格式检查，以及 v2 的签名和序列校验。未验证的短码地址只作为本次拨号候选。
2. **连接集成。** 在隔离网络让两个全新节点关闭 DHT、Bootstrap 和 Relay，用含可达地址的名片首次直连。隔离拓扑需要有通过公网过滤策略的测试入口。覆盖多个候选、部分失败、旧 IP 被其他节点使用、换 IP 后通过 DHT 回退、旧码转发和目标离线。DHT 用例须验收路由表、签名发布和按同一 ID 查到新地址三项证据。回归旧命令、手动暂停和显式 Multiaddr。
3. **用户入口。** 验收自己和好友名片都默认 52 字符、单一复制按钮、附带公网地址后生成短码、预览阶段不拨号。普通界面和失败提示只展示连接结果，高级诊断可看地址。
4. **真实网络。** 用不同网络上的节点验证发行引导节点短码、首次直连，以及换公网 IP 后同一旧码经 DHT 找到新地址并连回同一 ID。 [引导节点记录](dht.md#21-首次预置与运行时引导角色)
